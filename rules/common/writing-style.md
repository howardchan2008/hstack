# Writing Style: Human, Not AI

Applies to ALL prose for the owner: scripts, emails, founder copy, docs, posts.

## HARD BAN: em dashes, everywhere, including chat replies (2026-06-27)
No em dashes: drafts, deliverables, Claude's messages. Instant AI tell. Use period, comma, parentheses, rewrite. No dash-clause-dash cadence.

## HARD BAN: antithesis, "not X but Y" (2026-06-09, his #1 AI tell)
Banned forever: "It's not X, it's Y", "not just X but Y", "We don't do X. We do Y.", "More than X, it's Y", negation-then-pivot. State positive claim.
- BAD: "We're not a CRM, we're an execution layer." GOOD: "We're an execution layer for tutoring networks."

## Honorifics and politeness personas (2026-06-27)
Never first-name by default. Check address before comment, reply, DM, email: Dr/Prof/博士/先生 where held. Japan/East Asia default higher formality (family name + さん/様, keigo). Seniority & culture set register; unsure, err formal. Personas: peer founder, investor, professor, senior operator, student peer.

## Other AI tells
Avoid triplets. Banned vocabulary: delve, crucial, robust, comprehensive, nuanced, multifaceted, seamless, leverage, unlock, elevate, "in today's world", "at the end of the day", "that said". Banned openers: "What makes us different is", "Here's the thing", "Let's be honest". No over-balanced marketing, no hedge stacks.
Do: short, concrete, specific. Name number, person, place. One idea per sentence. Vary length.

## NO FULL LISTS BACK TO the owner (2026-08-20)
*"dont full list me, expose the decisions in session, even if u hv to generalize"*. Reply reports DECISIONS, not inventories.
- State decision & what changes. Generalise lookups ("ten tutors are waiting on the DBS step").
- Name individual only when he must act. File path is pointer; don't reproduce file.
- DONE: outcomes list, never records.

## FRAGMENTS, NOT COMPLETE DRAFTS (2026-08-26)
*"why ai drafts seem like ai, this is coz its too complete"*. WhatsApp/DM/iMessage: separate sends, 1-2 lines each. No recap, no summary. Fragments & dropped subjects correct. One idea per send. Email & formal correspondence EXEMPT.
Basis: 87,247 messages, median outbound 7-11 words, speaks after self ~50%.

## ONE DOC PER SUBJECT: APPEND, NEVER SPAWN (2026-08-26)
*"u keep making new docs rather than appending them to the existing one"*. 12 docs created 1 day; audit split 12 incomplete links.
- Before `to-gdrive`: canonical doc exists? Append & re-push SAME file.
- New doc: only unrelated or when recipient requests standalone.
- SOT tabs: prepend correction, not tab N+1. One subject, one home. ("100-tab cap" false; has 18 tabs.)
- Canonical: `~/Downloads/Personal/self-claims-verified-2026-08-22.md` (doc `12QdfJrXKHmWdFvAEy1PBrHdZE2M4ktVx_bIJC5T4cjs`).

## SHOW THE THING, AND SAY WHERE IT LIVES (2026-08-31)
*"u never shown me 47 occasions, change this behavior permanently, coz u often point me to smt but dont show where the document is"*. Never name set without showing. Never name doc without path/URL. Every file/doc/sheet/artifact ref = full path or URL, same sentence, every time.

THE TEST (separates from NO FULL LISTS):
- Decide/approve/correct/check work → SHOW IN FULL. Path alone ≠ showing.
- Background detail → generalize + path.
- Too large → show each category with count + path. No samples as sets.
- Set questions arrive WITH set, same turn.
